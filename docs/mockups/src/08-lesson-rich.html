01 / Concept

A key becomes a stack

Without versioning, writing to an existing key overwrites and destroys the previous bytes. With it on, every write adds an immutable version, and a delete adds a marker instead of removing anything.

OperationWithout versioningWith versioning
PUT same keyreplaces bytesadds a new version
DELETE keybytes goneadds a delete marker

03 / On real AWS

What changes with a bill attached

costNoncurrent versions are billed
Versioning plus aws s3 rm --recursive frees nothing. Every deleted object becomes a noncurrent version. Add a lifecycle rule with NoncurrentVersionExpiration.
destructive
Deleting a specific --version-id is permanent. There is no marker to remove afterwards.
good to know
Version IDs are only unique within a key. Never treat them as global IDs.
04 / Recap
  • A versioned key is a stack; DELETE adds a marker on top.
  • Restore by deleting the marker, addressed by its version ID.
  • Every stored version is billed: plan a lifecycle rule.
