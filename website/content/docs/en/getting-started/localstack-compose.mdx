## The official example

Straight from the [official docs](https://docs.localstack.cloud/aws/getting-started/installation/#docker-compose):

```yaml
services:
  localstack:
    container_name: '${LOCALSTACK_DOCKER_NAME:-localstack-main}'
    image: localstack/localstack
    ports:
      - '127.0.0.1:4566:4566' # LocalStack Gateway
      - '127.0.0.1:4510-4559:4510-4559' # external services port range
      - '127.0.0.1:443:443' # LocalStack HTTPS Gateway
    environment:
      - LOCALSTACK_AUTH_TOKEN=${LOCALSTACK_AUTH_TOKEN:?} # required by latest
      - DEBUG=${DEBUG:-0}
      - PERSISTENCE=${PERSISTENCE:-0}
    volumes:
      - '${LOCALSTACK_VOLUME_DIR:-./volume}:/var/lib/localstack'
      - '/var/run/docker.sock:/var/run/docker.sock'
```

<Note title="A token is required">
  The `latest` image (2026.x) **requires a LocalStack account token**: `${LOCALSTACK_AUTH_TOKEN:?}` makes `docker compose up` fail without one. Without it the container exits with code 55 ("License activation failed").
</Note>

## What this repo changes, and why

Our [`compose.yaml`](https://github.com/shahadathhs/aws-with-localstack/blob/main/infra/compose.yaml) (in `infra/`) is the official example with **two deviations**:

| Deviation                                        | Reason                                                                                                                |
| ------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------- |
| `image: localstack/localstack:2026.9.0` (pinned) | Same as `latest` right now, but pinned so the whole team gets the same version. Bump the tag deliberately to upgrade. |
| `S3_SKIP_SIGNATURE_VALIDATION=${S3_SKIP_SIGNATURE_VALIDATION:-1}` | LocalStack's own default (`1`) skips signature and expiry checks on presigned URLs. Passing it through lets you set `0` in `.env` to enforce them, which the [presigned URLs](/en/s3/04-presigned-urls/) lesson needs. |

Everything else — required token (`${LOCALSTACK_AUTH_TOKEN:?}`), ports, `DEBUG`, `PERSISTENCE`, volumes — matches the official example exactly. We also **add** a healthcheck so `make up` (which runs `docker compose up -d --wait`) blocks until LocalStack is ready.

### Getting your token

1. Create a free account at [app.localstack.cloud](https://app.localstack.cloud)
2. Copy your auth token (Account → Auth token)
3. Put it in `.env`: `LOCALSTACK_AUTH_TOKEN=ls-...`
4. `make up`

## What each setting does

| Setting             | Why                                                                                                                     |
| ------------------- | ----------------------------------------------------------------------------------------------------------------------- |
| `4566`              | The single **gateway port** — every AWS service API is served here (S3, SQS, DynamoDB, Lambda, ... all on one endpoint) |
| `4510-4559`         | Port range for services that bind extra endpoints (e.g. Elasticsearch). Rarely needed.                                  |
| `443`               | HTTPS gateway (optional — remove if port 443 is taken on your machine)                                                  |
| `127.0.0.1:` prefix | Binds the port to **localhost only** — don't expose your emulator to the network                                        |
| `docker.sock` mount | **Required for Lambda** — LocalStack spins up sibling containers to execute your functions                              |
| `volume` mount      | Container-internal state (logs, cache), not your created AWS resources                                                  |

## Start, verify and stop

Run these from the repo root. The `Makefile` wraps the compose commands for you:

```sh
make up        # start in the background (waits for the healthcheck)
docker ps      # STATUS should show "Up ... (healthy)"
make status    # health check: curl localhost:4566/_localstack/health, pretty-printed
make logs      # tail LocalStack logs
make down      # stop
make clean     # stop and DELETE all data
```

Services report `available` until first use, then `running`.

<Destructive title="make clean deletes data">
  `make clean` runs `docker compose down -v` and then removes the `volume` and `.localstack-data` directories. Everything LocalStack stored is gone.
</Destructive>

The compose file lives in `infra/`, so a plain `docker compose up` from the repo root fails with "no configuration file provided". If you want to run a raw compose command yourself, use the form the Makefile uses:

```sh
docker compose --project-directory . -f infra/compose.yaml <command>
# e.g. up -d --wait | down | logs -f localstack
```

## Troubleshooting

- **Container exits (55) with "License activation failed"** → the image is `latest`/2026.x without `LOCALSTACK_AUTH_TOKEN`. Either pin `4.9.0` or provide a token.
- **`make up` fails with "LOCALSTACK_AUTH_TOKEN not set"** → that's the official `${...:?}` syntax demanding a token; this repo's compose file uses it too, so set the token in `.env`.
- **Port already in use** (4566 or 443) → change the left side of the mapping, or drop the `443` line.
- **Lambda fails to start** → the `/var/run/docker.sock` mount is missing.
- **Startup stuck on `health: starting`** → give it ~15s on first boot; then check `make logs`.

<Recap>

- One gateway port (`4566`) serves every service, bound to localhost only; the `docker.sock` mount is what makes Lambda work.
- The compose file in `infra/` is the official example plus a pinned image and a healthcheck, and it needs `LOCALSTACK_AUTH_TOKEN` in `.env`.
- Use `make up`, `make status`, `make logs`, `make down` and `make clean` from the repo root; `make clean` wipes your data.

</Recap>
