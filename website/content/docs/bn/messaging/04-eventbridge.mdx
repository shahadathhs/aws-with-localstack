## বিষয়বস্তু দেখে routing

SNS ফিল্টার করে তোমার জোড়া attribute দেখে। **EventBridge** route করে event-এর নিজের বিষয়বস্তু দেখে। Producer একটি **event bus**-এ JSON event রাখে; bus-এর প্রতিটি **rule**-এ একটি **event pattern** থাকে; যে event মেলে সেটি যায় ওই rule-এর **target**-এ (একটি SQS queue, Lambda ফাংশন, SNS topic ও আরও অনেক কিছু)।

অংশগুলো:

- **Event bus**: যে চ্যানেলে event রাখা হয়। প্রতিটি account-এ একটি default bus আছে, আর নিজের বানাতেও পারো।
- **Event**: `source` (কে পাঠাল), `detail-type` (কী ধরনের event) আর মুক্ত-গঠনের `detail` object সহ JSON।
- **Rule**: একটি pattern আর এক বা একাধিক target। একটি event কয়েকটি rule-এর সঙ্গে মিলে তাদের সব target-এ যেতে পারে।
- **Pattern**: event-এর আদলে একটি JSON। প্রতিটি ফিল্ড গ্রহণযোগ্য মানগুলো array হিসেবে লেখে, আর বাদ দেওয়া ফিল্ড সবকিছুর সঙ্গে মেলে।

Pattern `detail`-এর ভেতরেও যেতে পারে, আর সংখ্যা তুলনা করে: `{"total": [{"numeric": [">", 100]}]}` শুধু ১০০-র বেশি total মেলায়।

```sh
export AWS_PROFILE=localstack

  --attribute-names QueueArn --query Attributes.QueueArn --output text)

  "detail-type": ["OrderPlaced"],
```

## SNS না EventBridge

| | SNS | EventBridge |
| --- | --- | --- |
| মডেল | topic-এ publish | bus-এ event রাখা |
| Routing | message attribute-এর ওপর filter policy | পুরো event-এর ওপর pattern, `detail`-এর ফিল্ডসহ |
| Subscriber | topic-এর সবাই, ফিল্টার না থাকলে | প্রতিটি rule-এর pattern যা বাছে |
| উপযোগী | এক ধরনের message অনেক consumer-কে broadcast | অনেক সার্ভিসের মধ্যে অনেক ধরনের event route করা |

সাধারণ নিয়ম: একজন publisher এক ধরনের message broadcast করলে SNS, আর অনেক সার্ভিসের মধ্যে অনেক ধরনের event ঘুরলে এবং প্রতিটি consumer আলাদা অংশ চাইলে EventBridge।

## রিয়েল AWS-এ যা বদলায়

<RealAws title="Target-এর অনুমতি লাগে">
  রিয়েল AWS-এ rule শুধু তখনই SQS queue-তে পাঠাতে পারে যখন queue-র policy `events.amazonaws.com`-কে পাঠাতে দেয়, আর Lambda ফাংশনে যখন তার resource policy দেয়। নইলে rule মেলে কিন্তু কিছুই পৌঁছায় না। LocalStack এটি প্রয়োগ করে না, তাই ল্যাব এ ছাড়াই চলে।
</RealAws>

<RealAws cost title="Event-এর বিল হয়">
  Bus-এ রাখা custom event প্রতি মিলিয়নে চার্জ হয়, তাই বাচাল producer বিলে ধরা পড়ে। অন্য সার্ভিসের সাড়া দেওয়ার মতো জিনিস bus-এ রাখো, প্রতিটি অভ্যন্তরীণ খুঁটিনাটি নয়।
</RealAws>

<Note title="এখানেও delivery at-least-once">
  EventBridge একটি event একাধিকবার target-এ দিতে পারে, আর ব্যর্থ target-কে কিছুক্ষণ retry করে। এই phase-এর সর্বত্র যেমন, তোমার consumer-রা idempotent থাকুক।
</Note>

<Recap>

- Producer bus-এ event রাখে, আর মেলা pattern সহ প্রতিটি rule সেটি তার target-এ পাঠায়।
- Pattern source, type ও `detail`-এর ভেতরের ফিল্ডে মেলায়, সংখ্যা তুলনাসহ; না-মেলা event ফেলে দেওয়া হয়।
- এক ধরনের message broadcast করতে SNS, আর অনেক ধরনের event বিষয়বস্তু দেখে route করতে EventBridge।

</Recap>
