## Config কোড নয়

কোনো মান কোথায় থাকে তা ঠিক করে কে সেটি পড়তে পারবে আর কত দ্রুত বদলানো যাবে।

- **কোডে** (বা build-এ): repository-র সবাই পড়তে পারে, আর বদলাতে ডিপ্লয় লাগে। এখানে কখনো secret রেখো না।
- **Environment variable-এ**: ফাংশনে সেট করা, তাই যে ফাংশনটি *describe* করতে পারে সেই পড়তে পারে। এটি console-এ আর `get-function-configuration`-এ দেখা যায়, আর লগে কপি হয়ে যাওয়া সহজ।
- **Secrets store-এ**: runtime-এ একটি অনুমোদিত, নথিভুক্ত API কলে পড়া হয়, আর পুনরায় ডিপ্লয় ছাড়াই বদলায়।

AWS দুটি store দেয়:

| Store | কীসের জন্য | মন্তব্য |
| --- | --- | --- |
| **Secrets Manager** | পাসওয়ার্ড, API key, token | versioned, rotate করা যায়, প্রতি secret-এ বিল |
| **Systems Manager Parameter Store** | সেটিং ও হালকা secret | `/shop/log-level`-এর মতো স্তরবদ্ধ নাম; `String` বা এনক্রিপ্টেড `SecureString` |

## Secret-এর version থাকে

Secret আপডেট করলে সেটি overwrite হয় না। একটি **version** যোগ হয় আর **staging label** নামের লেবেল সরে: `AWSCURRENT` হলো ডিফল্টে তোমার কোডের পাওয়া version, আর তার আগেরটি হয় `AWSPREVIOUS`, যাতে roll back করা যায়।

<Lab title="secret আপডেট করো আর পুরোনোটি পড়ো" time="~৫ মিনিট">
  <Predict>
    তুমি `hunter2` দিয়ে একটি secret বানালে, তারপর নতুন মান `correct-horse` রাখলে। সাধারণ পাঠ কী দেয়, কোন লেবেল থাকে, আর পুরোনো মান কীভাবে পড়বে?

    <Answer>
      সাধারণ পাঠ দেয় **`correct-horse`**, `AWSCURRENT` version। দুটি version থাকে, লেবেল `AWSCURRENT` আর `AWSPREVIOUS`। `hunter2` ফেরত পেতে `--version-stage AWSPREVIOUS` চাও।
    </Answer>
  </Predict>
  <Run>
```sh
export AWS_PROFILE=localstack

aws secretsmanager create-secret --name shop/db-password --secret-string 'hunter2'
aws secretsmanager put-secret-value --secret-id shop/db-password --secret-string 'correct-horse'

echo "current:"
aws secretsmanager get-secret-value --secret-id shop/db-password \
  --query SecretString --output text
echo "labels:"
aws secretsmanager list-secret-version-ids --secret-id shop/db-password \
  --query 'Versions[].VersionStages' --output text
echo "previous:"
aws secretsmanager get-secret-value --secret-id shop/db-password \
  --version-stage AWSPREVIOUS --query SecretString --output text
```
<Output>
```text
current:
correct-horse
labels:
AWSCURRENT
AWSPREVIOUS
previous:
hunter2
```
</Output>
  </Run>
  <Verify>
    - ডিফল্ট পাঠ `correct-horse`
    - দুটি version আছে, একটি `AWSCURRENT` আর একটি `AWSPREVIOUS` (দুই লাইনের ক্রম আলাদা হতে পারে)
    - আগের মান এখনো পড়া যায়
  </Verify>
</Lab>

## Runtime-এ secret পড়ো

নিচের handler প্রথম কলে secret পড়ে একটি গ্লোবাল ভেরিয়েবলে রাখে, যে cache-এর সঙ্গে [এক্সিকিউশন মডেল পাঠে](/bn/lambda/01-execution-model/) পরিচয় হয়েছে। একই warm instance-এর পরের কলগুলো নেটওয়ার্ক কল এড়ায়। সে এটাও জানায় ফাংশনের environment-এ পাসওয়ার্ড আছে কি না।

<Lab title="যে ফাংশন নিজের secret নিজে আনে" time="~৬ মিনিট">
  <Predict>
    তুমি ফাংশনটি দুবার invoke করলে। তারপর একই পাসওয়ার্ড environment variable-এ রেখে আবার invoke করলে। প্রতি কলে `fetched` কী বলে, আর Secrets Manager না ডেকে এখন কে পাসওয়ার্ড দেখতে পারে?

    <Answer>
      `fetched` প্রথম কলে **true**, দ্বিতীয়টিতে **false**: warm instance cache-করা মান ব্যবহার করে। ফাংশন পুনরায় কনফিগার করলে সেটি আবার **true**, কারণ কনফিগারেশন বদলালে নতুন instance শুরু হয়, আর `in_env` হয় **true**। যে ফাংশনটি describe করতে পারে সে এখন `get-function-configuration` দিয়ে পাসওয়ার্ড পড়তে পারে।
    </Answer>
  </Predict>
  <Run>
```sh
mkdir -p /tmp/cfg && cd /tmp/cfg

cat > sec.py <<'PY'
import os

import boto3

client = boto3.client("secretsmanager")
cached = None


def handler(event, context):
    global cached
    fetched = cached is None
    if fetched:
        cached = client.get_secret_value(SecretId="shop/db-password")["SecretString"]
    return {"fetched": fetched, "length": len(cached), "in_env": "correct-horse" in str(dict(os.environ))}
PY
zip sec.zip sec.py
aws iam create-role --role-name lambda-role --assume-role-policy-document '{
  "Version": "2012-10-17",
  "Statement": [{ "Effect": "Allow", "Principal": { "Service": "lambda.amazonaws.com" }, "Action": "sts:AssumeRole" }]
}'
aws lambda create-function --function-name readsec --runtime python3.12 \
  --handler sec.handler --zip-file fileb://sec.zip \
  --role arn:aws:iam::000000000000:role/lambda-role
aws lambda wait function-active-v2 --function-name readsec

for i in 1 2; do
  aws lambda invoke --function-name readsec --cli-binary-format raw-in-base64-out out.json >/dev/null
  cat out.json; echo
done
```

এবার যা *করা উচিত নয়* তা করো: পাসওয়ার্ড একটি environment variable-এ রাখো, আর দেখো কে পড়তে পারে।

```sh
aws lambda update-function-configuration --function-name readsec \
  --environment 'Variables={DB_PASSWORD=correct-horse}'
aws lambda wait function-updated-v2 --function-name readsec

aws lambda invoke --function-name readsec --cli-binary-format raw-in-base64-out out.json >/dev/null
cat out.json; echo
aws lambda get-function-configuration --function-name readsec --query Environment.Variables
```
<Output>
```text
{"fetched": true, "length": 13, "in_env": false}
{"fetched": false, "length": 13, "in_env": false}
{"fetched": true, "length": 13, "in_env": true}
{
    "DB_PASSWORD": "correct-horse"
}
```
</Output>
  </Run>
  <Verify>
    - `fetched` প্রথমে `true`, তারপর `false`: দ্বিতীয় কল cache ব্যবহার করেছে
    - Environment variable-এর পর `in_env` হয় `true`, আর `get-function-configuration` পাসওয়ার্ড সাদা লেখায় ছাপে
  </Verify>
</Lab>

<Lab title="Parameter Store-এ সেটিং" time="~৩ মিনিট" collapsed>
  <Predict>
    তুমি `/shop/log-level` `String` হিসেবে আর `/shop/api-key` `SecureString` হিসেবে রাখলে। `/shop`-এর নিচের সবকিছু কীভাবে তালিকাভুক্ত করবে, আর এনক্রিপ্টেড মান সাদা লেখায় পড়তে কী যোগ করতে হবে?
    
    <Answer>

    </Answer>
  </Predict>
  <Run>
```sh
aws ssm put-parameter --name /shop/log-level --value info --type String
aws ssm put-parameter --name /shop/api-key --value k123 --type SecureString

aws ssm get-parameters-by-path --path /shop --query 'Parameters[].Name' --output text
aws ssm get-parameter --name /shop/api-key --with-decryption --query Parameter.Value --output text
```
<Output>
```text
/shop/log-level	/shop/api-key
k123
```
</Output>
  </Run>
  <Verify>
    - দুটি নামই তালিকাভুক্ত, আর decrypt করা মান `k123`
  </Verify>

## রিয়েল AWS-এ যা বদলায়

<RealAws title="Secret পড়ার অনুমতি ফাংশনের লাগে">
  রিয়েল AWS-এ execution role-কে ওই secret-এর ARN-এ `secretsmanager:GetSecretValue` অনুমতি দিতে হয়, আর যে key সেটি এনক্রিপ্ট করে তারও। LocalStack এটি প্রয়োগ করে না, তাই ল্যাব এ ছাড়াই চলে। একটি secret-কে অনুমতি দাও, `*` নয়।
</RealAws>

<RealAws cost title="Secret-এর আর কলের বিল হয়">
  Secrets Manager প্রতি মাসে প্রতি secret আর প্রতি ১০,০০০ API কলে চার্জ করে, তাই প্রতি invocation-এ secret পড়া টাকা ও সময় দুটোই খায়। উপরের মতো গ্লোবালে cache করো, আর নির্দিষ্ট বিরতিতে বা পড়া ব্যর্থ হলে refresh করো। Parameter Store-এর standard parameter বিনামূল্যে।
</RealAws>

<Note title="Rotation">
  আসল Secrets Manager একটি Lambda ফাংশন চালিয়ে নির্দিষ্ট বিরতিতে secret rotate করতে পারে, যা ডেটাবেসে ও secret-এ একসঙ্গে পাসওয়ার্ড বদলায়। তুমি যে staging label দেখলে, rotation সেগুলো দিয়েই নতুন মান নিরাপদে বসায়।
</Note>

<Recap>

- কোডে বা environment variable-এ রাখা secret repository পড়তে পারা বা ফাংশন describe করতে পারা সবার কাছে দৃশ্যমান।
- Secrets Manager লেবেলসহ version রাখে: ডিফল্টে `AWSCURRENT`, roll back-এর জন্য `AWSPREVIOUS`।
- Runtime-এ secret পড়ে গ্লোবালে cache করো; parameter সাধারণ সেটিং রাখে, আর `SecureString` সেগুলো এনক্রিপ্ট করে।

</Recap>
