## Sandbox-এর ভেতরে একটি handler

তুমি একটি zip আপলোড করো, যার ভেতরে একটি **handler**, অর্থাৎ `event` আর `context` নেওয়া একটি ফাংশন। তুমি কখনো সার্ভার চালু করো না। কল এলে প্ল্যাটফর্ম তোমার কোড আছে এমন একটি sandbox খুঁজে নেয়, তার ভেতরে handler চালায়, আর পরের কলের আশায় sandbox-টি কিছুক্ষণ ধরে রাখে।

- **Cold start**: কোনো sandbox ফাঁকা নেই, তাই প্ল্যাটফর্ম নতুন একটি বানায়, কোড লোড করে আর তোমার top-level কোড চালায়। এটিই ধীর পথ।
- **Warm start**: একটি sandbox আগে থেকেই আছে এবং অলস, তাই শুধু handler চলে। গ্লোবাল ভেরিয়েবলে যা রেখেছিলে তা এখনো আছে।
- **Concurrency**: প্রতিটি sandbox একসময়ে একটি কল সামলায়। একসঙ্গে দশটি কলের জন্য দশটি sandbox লাগে, তাই প্ল্যাটফর্ম যতগুলো দরকার ততগুলো চালু করে।

ফলাফল: গ্লোবাল ভেরিয়েবল একটি cache, যা থাকতেও পারে, নাও পারে। একই sandbox ব্যবহার করা কলগুলো সেটি ভাগ করে, অন্য সব sandbox-এর কাছে সেটি অদৃশ্য। যা সঠিক হতেই হবে তা এতে রেখো না।

| সেটিং | ডিফল্ট | সীমা |
| --- | --- | --- |
| Timeout | ৩ সেকেন্ড | ১৫ মিনিট পর্যন্ত |
| Memory | ১২৮ MB | ১২৮ MB থেকে ১০,২৪০ MB, সঙ্গে CPU-ও বাড়ে |
| Payload | | উত্তরের জন্য অপেক্ষা করা কলে প্রায় ৬ MB |

## ডিপ্লয় ও invoke

ফাংশনের একটি **execution role** লাগে: যে পরিচয়ে সে চলে, আর Lambda তোমার হয়ে সেটি assume করে ([IAM রোল](/bn/iam/01-principals-users-roles/) দেখো)। LocalStack রোলের অনুমতি প্রয়োগ করে না, কিন্তু রোলটি থাকতে হয়।

<Lab title="যে counter টিকে থাকে" time="~৫ মিনিট">
  <Predict>
    নিচের handler প্রতি কলে গ্লোবাল `count`-এ এক যোগ করে ফেরত দেয়। এক সেকেন্ড পরপর তিনবার invoke করলে তিনটি কল কী ফেরত দেবে?

    <Answer>
      **১, ২, ৩।** প্রথম কল একটি sandbox চালু করে এবং top-level কোড চালায়, তাই `count` শুরু হয় ০ থেকে। পরের দুটি কল সেই sandbox-ই ব্যবহার করে, আর `count` চলতে থাকে।
    </Answer>
  </Predict>
  <Run>
```sh
export AWS_PROFILE=localstack
mkdir -p /tmp/lam && cd /tmp/lam

cat > handler.py <<'PY'
import time

started = time.time()
count = 0


def handler(event, context):
    global count
    count += 1
    return {"count": count, "age": round(time.time() - started), "event": event}
PY
zip handler.zip handler.py

aws iam create-role --role-name lambda-role --assume-role-policy-document '{
  "Version": "2012-10-17",
  "Statement": [{ "Effect": "Allow", "Principal": { "Service": "lambda.amazonaws.com" }, "Action": "sts:AssumeRole" }]
}'

aws lambda create-function --function-name counter --runtime python3.12 \
  --handler handler.handler --zip-file fileb://handler.zip \
  --role arn:aws:iam::000000000000:role/lambda-role
aws lambda wait function-active-v2 --function-name counter
```

`handler.handler` মানে ফাইল `handler.py`, ফাংশন `handler`। এবার তিনবার কল করো:

```sh
for i in 1 2 3; do
  aws lambda invoke --function-name counter --payload '{"hello":"world"}' \
    --cli-binary-format raw-in-base64-out out.json --query StatusCode --output text
  cat out.json; echo
  sleep 1
done
```
<Output>
```text
# the age value depends on your timing
200
{"count": 1, "age": 0, "event": {"hello": "world"}}
200
{"count": 2, "age": 1, "event": {"hello": "world"}}
200
{"count": 3, "age": 3, "event": {"hello": "world"}}
```
</Output>
  </Run>
  <Verify>
    - `count` চলে ১, ২, ৩: গ্লোবাল ভেরিয়েবল টিকে ছিল, কারণ একই sandbox তিনটি কলই সামলেছে
    - `age` বাড়ে: top-level কোড একবারই চলেছে, sandbox চালু হওয়ার সময়
    - `event` হুবহু সেই JSON, যা তুমি `--payload`-এ দিয়েছিলে
  </Verify>
</Lab>

## রিয়েল AWS-এ যা বদলায়

<RealAws cost title="সময় আর memory-র দাম দিতে হয়">
  বিল হয় অনুরোধের সংখ্যা আর duration গুণ কনফিগার করা memory ধরে। বেশি memory মানে বেশি CPU-ও, তাই বড় সেটিংয়ে কাজ আগে শেষ হয়ে একই বা কম খরচ পড়তে পারে। যে ফাংশন ঘুমায়, ঘুমানোর সময়ের জন্যও তার দাম দিতে হয়।
</RealAws>

<Note title="Cold start হুবহু সিমুলেট হয় না">
  LocalStack প্রতিটি ফাংশন তোমার মেশিনে একটি container-এ চালায়, তাই প্রথম কল ধীর হয়, কিন্তু সেই সময় থেকে আসল cold start সম্পর্কে কিছু জানা যায় না। সেটি AWS-এ মাপো।
</Note>

<Note title="বাস্তবে গ্লোবাল state">
  যা বানাতে খরচ বেশি অথচ আবার ব্যবহার নিরাপদ, যেমন SDK client বা ডেটাবেস কানেকশন, তার জন্য গ্লোবাল ব্যবহার করো। counter বা অন্য instance-এর যা দেখা দরকার, তার জন্য নয়।
</Note>

<Recap>

- ফাংশন হলো sandbox-এ থাকা handler, যা warm থাকা পর্যন্ত প্ল্যাটফর্ম বারবার ব্যবহার করে; গ্লোবাল ভেরিয়েবল সেই sandbox-এর সঙ্গেই বাঁচে-মরে।
- Concurrency মানে বেশি sandbox: সমান্তরাল কল গ্লোবাল ভাগ করে না।
- Timeout কলটিকে ব্যর্থ করে, অনুরোধটিকে নয়, তাই শুধু status code নয়, `FunctionError`-ও দেখো।

</Recap>
